# Reports process

- We implement reports as ReSpec documents, tracked in GitHub
repositories, using GitHub Pages to make them publicly readable, and
GitHub issues to track requirements or problems. Each report should
have an assigned task force. Each report should have one or more
editors.
- ReSpec can be used for tutorials, proposals, early and incomplete
versions of reports, or other HTML documents in repositories. Any HTML
document in a CG repo that uses ReSpec and is not at Draft or Final
stage should have the status "unofficial".
- Draft status indicates an intent to move a report to Final status.
Task forces decide by consensus when a report reaches Draft status and
requires wider review and implementation. Task forces notify the
Community Group on the mailing list when a report reaches Draft
status. Task forces coordinate with chairs to publish Draft reports.
- Task forces can make as many edits and updates as necessary to the
Draft report; updated reports should stay at the same URL.
- Final status marks a report as the best available guidance by the
Community Group. The CG decides through consensus to publish the
report as Final, considering factors such as outstanding issues,
sufficient review (including for topics from W3C Document Review) and
sufficient implementations to show interoperability. Final reports are
published by the W3C.
